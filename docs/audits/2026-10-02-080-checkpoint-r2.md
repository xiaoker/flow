## Object and authority contract

`/api/v1/admin/pipeline-window/checkpoint` supports authenticated POST and GET.
References specify runKey, bound targetDate, producer SHA, stage, input digest,
bundle digest, current lease owner and attempt. Keys are deterministic:

`market-data/pipeline/checkpoints/v1/<runKeySHA256>/<producer>/<stage>/<input>/<bundle>.json`

Only ordinary DISPATCHED/RUNNING rows with matching bound date/owner/attempt and
at least 30 seconds lease remaining can access objects. Recovery remains with
the existing recovery authority; this endpoint rejects recovery rows. D1 uses
the existing indexed exact runKey lookup with LIMIT 1; no writes or table added.

POST validates bounded bytes/digest, reconfirms authority, uses conditional
`If-None-Match: *` with R2 checksum enforcement and always verifies a full exact
readback before reporting verified. GET validates metadata, size and all bytes.
Both reconfirm authority after reading. Expired writes may leave an immutable
orphan but cannot imply stage completion. Existing objects are never overwritten.
There is no bucket listing, caller-supplied arbitrary key or active pointer write.

R2 conditional behavior was checked against the official API reference:
https://developers.cloudflare.com/r2/api/workers/workers-api-reference/

## Bounds and accounting

- Transport object limit **1 MiB**, distinct from the offline bundle format's
  larger ceiling. No automatic splitting or limit increase. Real large outputs
  need approved canonical artifact references, not unchecked large Worker bodies.
- Worker consumes at most 512 stream chunks and bounded buffers; does not parse
  the offline bundle or run model calculations. CPU/latency under free Workers
  limits remain unmeasured until a separately authorized canary.
- POST: at most three indexed D1 reads, one conditional R2 put and one get.
  GET: at most two indexed D1 reads and one get. Physical D1 rowsRead is UNKNOWN
  because the existing first() lookup does not expose meta; rowsWritten is zero.
- Client serializes calls, caps HTTP requests at 12, disables implicit retries
  and redirects, uses connect/read timeouts 5/10 seconds and response deadline
  20 seconds with 1 MiB cap. Lease RPCs have their own existing bounded budget.
- Lost upload response or server 5xx allows one readback, never repeat POST.
  Other errors fail closed. Unconfirmed write outcomes remain explicitly marked.
- Bytes sent/received and request/upload attempts are measured. Account remaining
  is UNKNOWN, not inferred from limits; this is not production budget admission.

Runner verifies approved expected digests, execution binding and adapter receipts
before reuse. Per-file restore checks use cooperative heartbeat, with fresh
authority confirmations at stage boundaries, avoiding one D1 poll per file.
Transport failure blocks checkpoint completion; an already valid local receipt
can be verified again without blindly repeating official collection.
