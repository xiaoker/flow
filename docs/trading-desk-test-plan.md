# 个人资金流向交易台测试与验收计划

日期：2026-07-16

适用范围：Phase 0 数据可行性验证与 Phase 1 MVP

状态：数据、发布链路与 Access 私有入口均已配置，生产安全冒烟验收已通过

## 0. 生产验收记录

2026-07-16 已完成以下实测：

- 未登录访问 `https://flow.xiaoker.com/` 被 Cloudflare Access 重定向至身份验证页；
- GitHub Actions `Cloudflare Access smoke #2` 从海外 Runner 使用 Service Auth 身份读取 `/api/v1/data-status` 并通过响应契约校验；
- 直接访问 `flow.xiaoker.workers.dev` 返回 `404`，Worker Preview URL 已关闭；
- `Daily market data #3` 已完成官方数据采集、质量门禁、D1/R2 发布和证据保留；
- 短时间内重复手动执行时，上交所接口可能对 GitHub 海外 Runner 返回 `403`。此时任务在采集阶段失败，不执行发布，生产继续读取上一个有效快照。日常定时任务保持每个工作日一次，不连续手动重跑。

## 1. 测试目标

上线前必须证明：

1. 官方数据能被稳定解析，字段变化不会静默产生错误结果；
2. ETF 估算净申购、融资余额变化和南向净买入公式及单位正确；
3. ETF、互联互通、两融可以独立、原子地发布；
4. 失败时继续读取上一有效版本，不出现半批新旧数据；
5. 页面始终展示统计日期、来源、口径、可信等级和异常状态；
6. 所有生产入口仅本人可访问，默认域名和预览地址不能绕过 Access；
7. 日常运行和历史回填不会突破免费额度保护线。

## 2. 测试环境与样本

- 本地：Python 流水线、临时 SQLite/D1、Worker 本地环境和前端 fixture；
- CI：Pull Request 中运行 lint、类型检查、单元测试、契约测试和构建；
- 预览：Worker Preview URL 已关闭，避免形成绕过 Access 的入口；
- 生产：仅执行只读冒烟测试和一次最小数据发布验证。

每个数据源至少保留以下 fixture：正常交易日、空响应、超时、字段新增、字段删除、字段改名、单位变化、重复记录、非交易日和一份真实异常样本。Fixture 必须记录抓取时间、源 URL、响应哈希和适配器版本。

## 3. 自动化测试矩阵

### 3.1 适配器与数据契约

| 编号 | 场景 | 预期结果 |
|---|---|---|
| DATA-001 | 正常官方响应 | 输出统一 schema，代码、日期、数值和单位正确 |
| DATA-002 | 必填字段删除或改名 | 适配器失败并记录具体字段，不写 D1 |
| DATA-003 | 新增未知字段 | 保留原始快照；解析结果不受影响并记录 schema 差异 |
| DATA-004 | HTTP 超时/限流 | 指数退避重试最多三次，仍失败则保持旧版本 |
| DATA-005 | 空响应或 HTML 错误页 | 不得解析为零行正式数据 |
| DATA-006 | 重复业务主键 | 硬性校验失败，不发布 |
| DATA-007 | 元/万元/亿元、股/万股混用 | 统一到标准单位，并通过已知样本断言 |
| DATA-008 | 非交易日触发任务 | 标记为无需更新，不生成伪造交易日记录 |

### 3.2 指标公式与分类

| 编号 | 场景 | 预期结果 |
|---|---|---|
| CALC-001 | ETF 当日与前日份额、净值齐全 | 净申购金额等于份额差乘单位净值 |
| CALC-002 | ETF 净值未发布 | 使用收盘价估算，等级和 warning 正确；净值到达后回补 |
| CALC-003 | ETF 首日上市或缺前值 | 指标为空并说明原因，不显示为零 |
| CALC-004 | ETF 拆分/折算 | 触发公司行动规则；未识别时阻断该数据域发布 |
| CALC-005 | 融资余额前后两日齐全 | 只命名为“融资余额变化”，单位正确 |
| CALC-006 | 南向买卖金额齐全 | 净买入等于买入减卖出 |
| CALC-007 | 请求北向实时净流入 | API 不提供该字段，页面显示披露限制 |
| CALC-008 | ETF 主分类唯一性 | 每只 ETF 在分类版本中最多一个主分类 |
| CALC-009 | 主题/策略/跨境产品 | 不进入宽基或行业榜，排除原因可查询 |
| CALC-010 | 行业映射缺失 | 进入“待分类”，不丢明细、不参与行业汇总 |
| CALC-011 | 1/5/20 日窗口覆盖不足 | 返回 coverage 状态，不把缺失历史当零值 |

### 3.3 发布状态机与幂等性

| 编号 | 场景 | 预期结果 |
|---|---|---|
| REL-001 | 同一输入重复执行 | 结果相同，无重复业务记录 |
| REL-002 | 分批写入在中间失败 | 新版本保持 `STAGED/FAILED`，旧 `ACTIVE` 不变 |
| REL-003 | 质量检查失败 | 不执行发布切换，`quality_issue` 可定位到规则和 run |
| REL-004 | 最终切换任一语句失败 | 整个切换回滚，每个数据域仍只有一个 `ACTIVE` |
| REL-005 | ETF 发布成功、两融失败 | ETF 日期更新，两融继续展示旧日期和 stale 状态 |
| REL-006 | 同一日期补跑 | 新 release 成功后旧 release 变为 `SUPERSEDED` |
| REL-007 | R2 上传成功、D1 写入失败 | 可直接从 R2 中间产物重放，不重新请求源站 |
| REL-008 | C 级来源失败 | A/B 数据域正常发布，只产生可选源告警 |

### 3.4 API、性能与缓存

| 编号 | 场景 | 预期结果 |
|---|---|---|
| API-001 | 正常聚合请求 | 信封包含 `asOf`、`releaseId`、coverage、等级和 warning |
| API-002 | 日期或周期非法 | 返回 `400` 和稳定错误码 |
| API-003 | 请求超出覆盖范围 | 返回缺口说明，不返回伪造零值 |
| API-004 | 排行榜 limit 大于 50 | 拒绝或截断至 50，并记录契约行为 |
| API-005 | 时间区间超过 3 年 | 返回 `400` |
| API-006 | 带匹配 ETag 重试 | 返回 `304`，不重复传输响应体 |
| API-007 | 聚合接口查询计划 | 使用目标复合索引，无无界全表扫描 |
| API-008 | 数据域版本不同 | 各卡片使用自己的 `asOf`，页头完整日期计算正确 |

性能基线：个人网络环境下，缓存未命中时主要 API 的服务端 P95 小于 500 ms；总览首屏在普通宽带下 3 秒内可交互。性能不达标时先检查查询行数、索引和响应体，再考虑新增缓存组件。

## 4. Phase 0 放行门槛

Phase 0 结束、允许进入页面开发前必须满足：

- 连续三个交易日成功采集 ETF、互联互通和两融数据；
- 每个核心数据源至少完成一组契约 fixture；
- 标准字段字典确认代码、日期、时区、金额和数量单位；
- 三个核心公式通过手工样本和自动化测试双重核对；
- R2 原始快照可以重放到临时 D1；
- 模拟一次字段删除和一次 D1 中途失败，均未改变旧 `ACTIVE`；
- 明确各数据域的实际发布时间和 stale 阈值。

未达到上述条件时，不以临时硬编码或关闭质量规则的方式进入 Phase 1。

## 5. Phase 1 用户验收

使用真实生产数据完成一次桌面端验收：

1. 登录后 60 秒内判断主要宽基和行业的 1/5/20 日资金方向；
2. 查看 ETF 指标公式、数据来源和更新时间；
3. 查看南向净买入及北向披露限制；
4. 查看沪深两融汇总、行业变化和个股排名；
5. 人为制造一个 stale 数据域，确认其他模块仍正常；
6. 手动补跑指定日期，确认版本切换和审计记录；
7. 从未登录浏览器验证所有默认域名和预览地址均不可绕过。

## 6. CI 与发布门禁

Pull Request 必须通过：

- Python lint、类型检查、单元测试和适配器契约测试；
- D1 migration 在临时数据库的升级与查询测试；
- Worker 类型检查、API 契约测试；
- React/vinext 生产构建、页面与 API 回归测试；
- fixture 中不得出现账号、Token 或 Cookie；
- 依赖漏洞检查不得存在已知高危项。

生产发布后自动执行只读检查：Access 拦截、`/api/v1/data-status`、总览响应 schema、最新数据日期和关键页面元素。任何安全检查失败立即视为发布失败。
