# 交易台数据质量合同

本产品的所有页面判断都必须满足：**来源可追溯、日期可对齐、代码可匹配、单位可复算、缺失不补造**。任何一项不满足，结果只能进入待核验区，不能替换线上发布快照。

## 数据分层

| 层 | 必须保存 | 发布前检查 |
| --- | --- | --- |
| 原始层 | 官方 URL、请求参数、响应原文、HTTP 状态、观察时间、SHA-256 | 域名白名单、响应非空、哈希稳定 |
| 规范层 | `trade_date`、市场、代码、官方名称、原始单位、规范单位、日期语义 | 字段类型、单位换算、代码格式、来源/市场一致、同日重复值无冲突 |
| 派生层 | 公式版本、输入行键、窗口日期、覆盖数量、结果 | 全窗口覆盖、没有跨缺口差值、结果可由规范层重算 |
| 发布层 | 快照日期、来源状态、质量报告、发布哈希 | 任一 critical 失败即 pending；页面只读 confirmed 快照 |

## ETF 硬规则

1. 业务键是 `market + instrument_code + trade_date`，不按页面行号或名称匹配。
2. `1d/3d/1w/2w/1m/3m/6m/12m` 必须分别有 `1/3/5/10/21/63/126/252` 个相邻官方份额变化点；少一个就返回 `null`，页面显示“覆盖不足”。
3. ETF 金额估算必须逐日使用同日官方 NAV；缺 NAV 不估算，不使用当前 NAV 代替历史 NAV。
4. 当某市场的 previous row 不是官方参考市场（SSE）紧邻前一交易日时，不能把跨日差值标记为 `1d`。
5. 板块汇总只累加通过完整窗口门禁的 ETF，并输出可比数量；没有组成的周期不输出 0 伪值。

## 自动化门禁

- Python `trading-desk qa-release`：原始→规范→快照逐层对账，并检查派生窗口、金额覆盖、板块组成。
- Worker `admin/import`、`admin/history-import`：服务端再次检查派生终端；失败只归档 `pending`，不写入 active dashboard。
- Worker 单元/渲染测试：验证部分状态不会被聚合为完整多周期数据。
- 定时任务失败、来源缺失或日期不完整时，保留原始证据并在下一轮补采；不使用“最近可用值”填充当前交易日。

## 人工抽查清单

每次发布至少抽查 3 个 ETF（沪市、深市、跨市场分类各一）：打开原始文件，核对代码、简称、交易日、份额、NAV、单位；再用公式独立计算 1d 和一个长周期。抽查结果连同发布哈希保留在运行 artifact 中。
